A / judgment calls

1 · One row model for all six providers

Today each provider has its own body component rendering its own state shape. Rows and summary cards both need the same thing: a flat list of windows. Add a pure function that normalises each provider state into one shape, and build both new views on it.

type QuotaRowModel = {
  plan: string | null;              // "Max", "Pro 5x", tier name
  planNote: string | null;          // "renews 08/29, 17:19"
  windows: { id; label; remainingPercent: number|null; resetAtMs; resetLabel; periodHours }[];
  resetCredits?: { available: number; next: {...}[] }   // Codex only
};
toQuotaRowModel(provider, state, t) => QuotaRowModel

Lives next to resetSchedule.ts, React-free, unit-tested. The existing provider bodies stay as they are for the Auth Files compact card, so bindQuotaClasses and both skins are untouched.

Alternative: port the six bodies to a horizontal skin

Faster to start, but the summary cards would still need aggregate logic reading six shapes, and the row layout per provider would drift. Not recommended.

2 · Summary card headline = sum of remaining across credentials

Match the screenshot: pick the provider's longest window (7-day / weekly / monthly), sum remaining percent over loaded credentials, denominator is credentials × 100%. One bar segment per credential, coloured with the existing meter thresholds; unloaded credentials render a grey segment and the numerator shows -- when nothing is loaded. Footer is the soonest reset among loaded credentials, using resetSchedule.ts exclusions.

Claude gets a second line for the model-specific 7-day windows (Fable 5 etc.) behind a Show/Hide link, as in the screenshot. Other providers with several long windows (Antigravity groups) show the first.

Alternative: show an average instead of a sum

"87% avg remaining" reads more naturally than "436% of 500%", but loses the at-a-glance headroom count. Say the word and I'll switch.

3 · Redaction rule and persistence

Header toggle (existing ToggleSwitch) next to Refresh all. When on, every identity string on the page goes through one helper:

redactIdentity("claude-theo@lambda.dev.json")  // "claude-t•••@l•••.dev.json"
redactIdentity("codex-4630970a-abc@one.dev-pro.json") // "codex-4630970a-a•••@o•••.dev-pro.json"
redactIdentity("kimi-account.json") // "kimi-a•••.json"

Rule: split on @; in each part, keep everything up to and including the first char after the last - (or first char if no dash), mask the rest of that word with •••, keep the TLD/extension tail. Applies to file names, Devin emails, timeline lane labels and row tooltips. Default is visible; the choice persists in localStorage like the Auth Files compact mode so it survives a restart before you share your screen.

Alternative: default redacted, or sessionStorage only

Default-redacted is safer for streaming but annoying day to day. sessionStorage matches the page's tab/sort prefs but forgets before the next call. Either is a one-line change.

4 · What happens to tabs, sort, pagination, timeline

Keep
  • Provider tabs, now filtering which sections render.
  • Sort mode, applied within each section.
  • Timeline below the sections, unchanged, but fed all visible rows.
  • Click-to-load, Devin auto-fetch, cache generation guards, per-row Refresh and Codex Reset with confirm.
Drop
  • Pagination. Rows are ~60px, so 30 credentials fit without paging.
  • The card grid and QuotaCard on this page (the component stays for nothing else, so it is deleted along with its module).
Alternative: keep pagination

Keep the existing per-page slicing applied across the flattened row list. Sections would then split across pages, which looks odd. Recommend dropping.
